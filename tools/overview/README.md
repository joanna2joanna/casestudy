# 案例总览数据（overview）

根目录 `overview.html` 是「客流 × 娱乐值」总览页的成品，本目录是它的数据与生成脚本。

## 做完一个新案例后，这样更新总表

1. **编辑 `data.json`**，在末尾加一行新案例，字段照抄现有行：

   - `slug`：案例文件夹名（必须与首页卡片一致）
   - `name` / `location` / `desc`：首页卡片上的名称、地点、关键描述
   - `chapter` / `subgroup`：所属章 / 子组，见现有行枚举（如 `中国`、`新加坡`）
   - `vis` / `chip`：客流值 + 口径标签。单园年度实值照抄案例页研究结果；累计／预计／估算一律在 chip 里写清，别混成年度
   - `pph` / `pph_src`：娱乐值（人/小时）。**只收园级合计**——优先 The Park DB 园页 Capacity 字段；没有就留空字符串 `""`，页面自动显示「暂无公开」。不要从单个设施的散数据自己加总

2. **重新生成**：`python3 tools/overview/gen.py`

3. **提交推送**：`git add` 后 commit + push（记得连首页新增卡片一起）

## 口径速记

- PPH 来源统一 The Park DB（TEA 研究伙伴）。例外：北京环球用的是本库 PPH 工具校验值（Park DB 未收录）
- 合集型案例（如华特迪士尼世界是度假区，不止四个园）不填单园 PPH，留空
- 两列互不换算：客流看热度，PPH 看产能
