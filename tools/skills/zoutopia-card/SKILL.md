# 走托邦·小红书文字卡片

把一篇走托邦公众号长文改成小红书风格的波普风文字卡片系列。

## 核心原则

- **文章多长节奏如何就切几张** — 不固定张数
- **每张一个节奏单元** — 不太空、不太满、话不说完、不讲太多不同内容
- **严格按原文换行** — 不打散、不合并、不另起行，用户原文换行即卡片换行
- **严格按原文顺序** — 不调换句子先后，封面例子在前主题句在后，正文卡逐句顺延
- **正文统一38px** — 只加粗+颜色区分，不放大字号
- **小红书独立编号** — Vol.01、Vol.02...不跟zoutopia drafts走
- **工作区放持久目录** — 不用`/tmp`（会被系统清理），用 `~/Projects/zoutopia-xhs/`

### 封面卡（第1张）

- 底色 #fffef5
- 页眉：金黄底(#F9A825)+白字品牌名+浅蓝字(#E3F2FD)Vol编号，padding: 22px 75px
- 标题：120px Noto Sans SC 900 #1E88E5，金黄阴影(#F9A825) 2px/2px，左对齐，不加标点
- 正文：38px #2d3436，行高1.6，段距46px
- 高亮和正文卡统一用 `.hl-red` `.hl-yellow` `.hl-teal`

### 正文卡（第2张起）
- 画布 1080×1350px，overflow: hidden
- 底色 #fffef7
- 页眉：同封面卡 + `border-right: 12px solid transparent`（对齐侧边条）
- 正文：38px #2d3436，行高1.5，段距38-50px（内容多时收紧到26-32px）
- 右侧彩虹条纹：`border-image` 在 `.body-text` 上，**绝不**单独定位侧边条

### 高亮三色纪律（强制）

| class | 效果 | 用途 | 示例 |
|-------|------|------|------|
| `.hl-red` | 粉色底划线 | **落点句、收束金句** | 「要有光」「造物主是我们自己」「宇宙·online」 |
| `.hl-yellow` | 黄色底划线 | **核心判断、关键概念** | 「答案不是等来的，是活出来的」「文化飞地」 |
| `.hl-teal` | 青色加粗 | **特殊术语、引号、书名、人名** | C罗·张雪《最后的问题》@rcswex |

不要用 `.hl-blue`，除非四个颜色确实不够区分。**同一概念全文高亮色一致**（如「宇宙·online」通篇红色）。

## 工作流

### 第一步：确认原文
1. **先让用户发发表版原文** — draft可能有差异
2. 全文写入工作目录
3. **不要动zoutopia drafts目录原文**
4. 确定小红书系列编号（Vol.01, Vol.02...）

### 第二步：去AI味（先诊断、后改动）
1. shuorenhua（scene: public-writing, standard, structural）→ 结构层
2. humanizer-zh → 词句层
3. **annotation mode：只标问题让用户确认，批准后才改动**
4. 改后全文保存为 `article-N-final.md`，去除 `---` 分隔符
5. **跑 voice-check 终检** → 过完 14 条红线再进切卡
6. ⚠️ **后续切卡/合并时若再改文字，改完立即回写到 final.md**，保持文本源头和卡片一致

### 第三步：排版方案（用户确认后再写HTML）

**先出方案，不写代码。** 三项一起给用户看：

1. **句间分组** — 哪些句子的 `</p><p>` 之间不空行紧贴、哪些保留段距
2. **合并方案** — 消除空行后 `<p>` 数下降，哪些卡可以合并少一张
3. **高亮计划** — 每张卡哪些句子用什么颜色，附三色理由

用户点过头再进第四步。中途若改主意（恢复原文、删重复句等），改完立即回写 final.md。

### 第四步：切卡
- **按确认的排版方案切**，不固定张数
- 封面卡 ~70-100字（标题+开篇钩子）
- 正文卡：一个节奏单元一张，原文自然分段顺延
- **严禁擅自加文字** — 用户原文没有的句子、比喻、展开，一个字都不补
- **合并后检查语义重复** — 同一张卡里、同一段落内，相邻两个画面是否在说同一件事

### 第五步：生成 HTML
- 封面用模板，正文用模板
- 页眉品牌名统一「说走就走的走托邦」
- **每行一个 `<p>`，严格按原文换行**
- 文件命名：`card-v{N}-{M}.html`，N=Vol编号，M=卡片序号

### 第六步：溢出检查（强制，不可跳过）

生成HTML后、截图前，**逐张数 `<p>` 标签数：**

单卡安全上限 **≤16行**。画布1350px，页眉~70px + padding ~110px = 可用~1170px，每行 38px×1.5 = 57px。

```bash
for f in card-v*.html; do
  c=$(grep -o '<p>' "$f" | wc -l | tr -d ' ')
  [ $c -gt 16 ] && echo "OVERFLOW: $f has $c lines (max 16)" || echo "OK: $f = $c lines"
done
```

⚠️ 用 `grep -o '<p>'` 而非 `grep -o '<p>[^<]*</p>'`——后者漏掉内含 `<span>` 的 `<p>` 标签。

输出 OVERFLOW 的卡立即拆，不等到截图才发现。**宁可多一页，不能丢一句。**

### 第七步：截图（Python Playwright 方法）

```python
from playwright.sync_api import sync_playwright

workdir = '<工作目录绝对路径>'
with sync_playwright() as p:
    browser = p.chromium.launch()
    for i in range(1, 8):  # 按实际张数
        page = browser.new_page(viewport={'width': 1080, 'height': 1350})
        page.goto(f'file://{workdir}/card-v{N}-{i}.html')
        page.screenshot(path=f'{workdir}/card-v{N}-{i}.png', full_page=False)
        page.close()
        print(f'OK: card-v{N}-{i}.png')
    browser.close()
```

⚠️ 不用 Chrome CLI 的 `--screenshot` 参数——macOS 新版本沙盒会给 PNG 加上隔离标记，导致 Finder 无法打开。Python Playwright 不触发此问题。

### 第八步：交付
- 让用户从 **Finder 手动打开** `<工作目录>/` 查看 PNG
- 不依赖 `open` 命令（沙盒限制）

### 第九步：部署
- 更新 `index.html` 的卡片系列列表（标题、张数、封面PNG）
- 完成后统一 commit + push：
```bash
cd ~/Projects/zoutopia-xhs
git add -A
git commit -m "Vol.NN: <标题>"
git push
```
- GitHub Pages 自动部署到 https://joanna2joanna.github.io/zoutopia-xhs/

## 踩过的坑

1. **侧边条咬到页眉** → 改用 `border-image`，不单独绝对定位
2. **页眉padding不统一** → 全系列 22px 75px
3. **正文字号反复放大裁切** → 最终定 38px
4. **去AI味后原文完全变了** → 必须让用户发发表版，重新对齐再切卡
5. **擅自改用户换行** → 严格按原文 `<p>`，不自己加换行逻辑
6. **编号混乱** → 小红书独立Vol编号
7. **张数僵化** → 文章多长节奏如何就切几张
8. **内容太密/太疏** → 每张一个节奏单元
9. **标题没对齐发表版** → 不能从draft文件名推导标题
10. **卡片底部被截断** → 加了溢出检查：`grep`数`<p>`标签，≤16行
11. **高亮颜色随意** → 定了红/黄/青三色纪律，不能凭感觉
12. **擅自加文字** → 用户原文没有的比喻/句子，一个字不补
13. **/tmp被系统清理** → 工作目录移到 `~/Projects/zoutopia-xhs/`
14. **body背景色漏出卡底** → body必须与卡片底色统一（封面 #fffef5、正文 #fffef7），不能留 #e8f5f0
15. **border-image成灰色竖条** → slice 值因 Chrome 版本而异。Joanna 的机器实测 `1` 正常、`100%` 灰色。**以模板为准：`1`。新机器先截一张正文卡确认颜色。**
16. **Chrome弹系统密码框** → `--password-store=basic` 不够，必须加 `--use-mock-keychain`
17. **溢出检查漏数** → `grep '<p>[^<]*</p>'` 漏掉含 span 的 p 标签，改用 `grep '<p>'`
18. **chromium版本号硬编码** → `chromium-1228` 过时，用 `chromium-*` 通配
19. **去AI味改动不可逆** → 改动前告知原文→改后，批准了再落笔；用户反悔立即回退
20. **相邻句语义重复** → 合并卡后检查是否有两句在说同一件事（如「没有影子」+「抹去了阴影」）
21. **高亮先出方案再写HTML** → 切卡时列出高亮计划，用户确认后再写入 HTML，避免反复改
22. **封面内容顺序** → 严格按原文序列：例子在前、主题句在后。不要自作主张调换顺序
23. **跨卡重复句子** → 调整卡片分布时，检查同一句话是否出现在两张卡里（如"最近的一些访谈…辩证思考"在 Card3 和 Card4 之间反复出现）
24. **卡片密度不均** → 9行以下的卡可以和前后合并或调整分布，最终各卡尽量分布在 9-15 行区间
25. **封面正文不空行** → 封面卡底部的几句正文之间不加 `margin-bottom` 空行，连续排列，参照原文换行
26. **截图用Python Playwright，不用Chrome CLI** → macOS新版本沙盒收紧，Chrome CLI截图打上provenance隔离标记导致Finder无法打开。统一改用Python Playwright screenshot，截图后让用户从Finder手动打开
